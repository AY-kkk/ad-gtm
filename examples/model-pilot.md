# 示例：电商素材团队的视频模型试点

本例为合成教学案例。下列任务量、阈值和成本仅用于演示设计与计算，不是客户实绩、市场价格或模型能力结论。

## 输入与诊断

客户团队想加快商品开头改版，但未确定是否应替换整个制作流程。

`ad-discovery` 先要求一周的真实任务、修改与工时记录；将“开头制作慢”作为待验证假设。优先试点产品亮相片，不把复杂机构、人物口播一并纳入。

## PoC 设计

`ad-poc` 设计三种方案：现有制作流程、Seedance 2.0 流程、Seedance 2.5 流程。每种方案使用同一组 6 个任务、相同商品资料和交付规格。2 个任务包含难处理的反光或细小结构，难例在执行前选定。

各模型允许适合自身的分段、提示词与后期；记录这些差异，因此比较对象是完整制作流程。若客户希望隔离模型因素，需要追加同输入的受控实验。

| 项目 | 本例约定 |
| --- | --- |
| 质量 | SKU、外形、文字和操作准确；商业主张有依据 |
| 尝试与预算 | 执行前确认上限，记录全部失败和人工处理 |
| 成本 | 每条合格成片成本，包含生成、人工、授权和后期 |
| 时效 | 从收到合格资料到可交付的总周期，另记人工工时 |
| 决策 | 质量达标且成本、周期满足客户阈值后，进入下一批试点 |

账号权限、实际服务、区域、完整模型 ID 和报价来源均需核验。六个任务可暴露问题，但不能证明规模化可靠性。

## 成本口径演示

假设某次流程实际记录为：生成费用 120 元、人工 180 元、后期 60 元、素材授权 0 元，最终 4 条成片通过。

```text
总制作成本 = 120 + 180 + 60 + 0 = 360 元
每条合格成片成本 = 360 / 4 = 90 元
```

这是算式示例，与任何模型价格无关。失败尝试的实际费用已经包含在 120 元中。若合格成片为零，报告 360 元已发生成本，单条合格成本不可计算。

## 商业落地

`ad-scale` 只依据真实验收结果提出下一阶段。假设产品亮相场景通过，可先扩展相近 SKU；新渠道、人物口播和复杂操作另设验证。

商业方案需明确交付频率、素材与账号责任、当前报价依据、验收、修改和支持范围。未得到采购确认前，阶段仍是试点；未产生投放数据前，不主张转化提升。

本例最终产物是 PoC 设计与成本口径演示，实际生成、验收、采购和投放状态均为 `not_run`。
