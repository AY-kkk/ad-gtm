# 客户诊断与场景选择

## 输入

客户类型、访谈记录、现有制作流程和可用数据。尚无客户材料时输出访谈提纲与待验证假设，不写成已确认客户事实。

## 方法

1. 区分使用者、验收人、业务负责人、预算与采购决策者；识别谁从改进中受益、谁承担切换成本。
2. 还原从 brief、素材、制作、修改到发布的流程。记录产量、周期、人工工时、成本、返工原因和资料来源。
3. 找到具体瓶颈：如开头迭代慢、SKU 扩展成本高、素材授权不足或人物产品交互失败。区分模型能力、服务接入和组织流程问题。
4. 筛选候选场景，逐项评价业务价值、频率、输入就绪度、可验收性、接入成本与失败代价。使用证据说明优先级，不用未经校准的总分替代判断。
5. 选择最小可验证场景，明确可用素材、当前基线、目标、验收人、资源和决策时间。关键条件未知时列出下一次访谈要确认的事项。

## 输出

客户问题卡、角色关系、流程瓶颈、候选场景对照表，以及优先场景的一页试点摘要。

摘要字段：`account_alias / opportunity_id / 场景 / 基线来源 / 价值假设 / 输入条件 / 验收人 / 预算状态 / 决策节点 / 未知项`。

## 完成标准与交接

事实、推断和待验证假设清晰分开；试点目标能用实际任务评估。可交给 `ad-poc` 设计对照试点，也可单独交付访谈与机会诊断。

## 示例

“团队每周都要重做商品开头”只证明工作存在；是否值得采购，还需当前工时、合格率、授权素材与决策角色的依据。
