# 模型 PoC 与单位成本

## 输入

客户场景、基线、代表性任务和难例、可用素材、验收要求、候选模型及预算。可直接使用用户资料或 `ad-discovery` 产物。

## 方法

1. 把业务问题写成可验证目标；明确交付规格、样本、质量门槛、验收人和决策日期，执行前约定继续、调整、停止条件。
2. 建立现有流程与候选模型的对照。工作流比较允许各模型采用适合的提示词和后期方式，记录差异；隔离模型因素的测试另固定输入及参数范围。
3. 核验具体厂商、服务、区域、完整模型 ID、任务模式、账号权限和当前费用，不能从发布公告推断账号可用性。
4. 覆盖普通任务和细节、动作等难例，预先约定每个任务允许的尝试与人工处理。记录全部失败、重试和修改，不能只报告最佳样片。
5. 需要制作时使用已安装的制作 Skill 或现有工具；本模块独立使用可完成试点设计和已有记录复盘，不依赖样片生成器。
6. 按相同标准验收，报告任务数、尝试数、通过数、完整周期与人工工时。区分片段通过率、成片通过率及其分母。
7. 用实际账单与工时计算成本；与基线保持同币种、规格和交付范围。缺数据时只输出模型与缺口，不估写实测结论。

```text
制作总成本 = 生成账单 + 人工成本 + 素材授权成本 + 后期成本
每条合格成片成本 = 制作总成本 / 验收通过的成片数
```

包括废片、重试和修改成本，投放费用单列。合格成片为零时单条成本不可计算，同时报告已发生成本。小样本未失败不能解释为可靠性已证明。

## 输出

使用[试点评估表](assets/pilot-scorecard.md)，交付对照设计或有证据的结果卡。结论覆盖质量、成本、时效与接入条件；未执行项标为 `not_run`。

## 完成标准与交接

每项通过结论可追溯到样本与标准；每项成本包含口径和来源。符合验收条件再交给 `ad-scale`；未通过时写明缩小范围、修正输入或停止的理由。
