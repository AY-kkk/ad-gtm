# Ad GTM 任务导航

把用户目标转化为最短可执行路径，保留项目事实和已完成产物。此入口负责选任务、传递资料和汇总交付，不替代专项 Skill。

## 输入

用户目标、已有资料、需要的交付物。先识别是品牌广告生产、广告实验，还是视频模型客户商业化；已有有效产物时直接从对应阶段开始。

## 选择路径

| 当前问题 | 选择的 Skill | 交付物 |
| --- | --- | --- |
| 产品卖点和受众还没明确 | `ad-brief` | 事实表与广告 brief |
| 不知道用什么角度表达 | `ad-creative` | 创意方向、脚本与开头变体 |
| 有创意，需要镜头和素材计划 | `ad-storyboard` | 分镜与制作包 |
| 确定使用 Seedance 2.0 | `ad-seedance-20` | 2.0 任务及提示词 |
| 确定使用 Seedance 2.5 | `ad-seedance-25` | 2.5 任务及提示词 |
| 需要检查脚本或实际成片 | `ad-review` | 问题清单与验收结论 |
| 需要测试素材或分析投放数据 | `ad-experiment` | 实验设计或结果分析 |
| 需要找客户场景与商业机会 | `ad-discovery` | 客户诊断与优先场景 |
| 需要验证模型是否能进入流程 | `ad-poc` | 对照试点与成本质量结论 |
| 需要将试点推进到采购与扩量 | `ad-scale` | 商业方案与落地计划 |

常用路径：

- 广告制作：brief → creative → storyboard → 指定模型 → review → experiment。
- 客户商业化：discovery → poc → scale；PoC 需要样片时接入广告制作路径。
- 素材改版：creative → 必要的 storyboard / 模型步骤 → review → experiment。

不要因版本号默认选择模型。用户未指定时，按已有账号、素材、交付要求与试点成本选择，必要时先列候选。

## 执行与交接

1. 输出此次路径和第一个交付物，随后直接处理已授权工作。
2. 在当前环境中定位并读取对应 Skill 的 `SKILL.md`。按顺序执行需要的环节；不要求后台多 Agent。
3. 向下一环节传递项目 ID、产物版本、来源、已确认约束、待确认项和完成状态。不要将创意假设升级为事实。
4. 每阶段只补影响交付的缺口。已有合格 brief 或分镜不必重写。
5. 总结已完成产物、当前阻塞和下一步。实际生成、发布和花费只在用户授权与可用工具范围内执行。

专项 Skill 未安装时，说明缺少哪个模块并提供本次任务清单；可按一般能力协助，但不声称已调用该模块。独立使用本入口时仍能完成任务规划。

## 输出与完成标准

输出“目标 → 所选 Skill → 输入产物 → 输出产物 → 当前状态”的任务表。状态为 `planned / running / completed / blocked`；检查结果另用 `not_run / pass / fail`。只有实际执行的阶段才能标为完成。

## 示例

“已有合格分镜，只要做 Seedance 2.0 制作包。” → 直接选择 `ad-seedance-20`，不重复 brief 或创意流程。
